# BBG000CL1HL7_2021-12-10: CLI (Mack-Cali Realty) renamed Veris Residential (VRE)

## 1. Verdict

Not a delisting. Mack-Cali Realty Corp changed its name to Veris Residential, Inc. and its ticker from CLI to VRE
effective 2021-12-10; the same common stock (CUSIP 554489104) kept trading on the NYSE. The library's
exchange-transfer ending is wrong: there should be no ending, and `ticker_history` should continue under VRE.

## 5. What happened

- On 2021-12-07 the company announced a rebranding: effective 2021-12-10 it becomes Veris Residential, Inc.,
  and its common stock, par $0.01, "will commence trading on the New York Stock Exchange under a new ticker
  symbol VRE" ([SEC 8-K 2021-12-07](https://www.sec.gov/Archives/edgar/data/924901/000110465921147037/tm2134737d1_8k.htm)).
- Fails rows for CUSIP 554489104: CLI through 2021-12-10 (10 rows from 2021-11-02), then VRE from 2021-12-16 to
  2022-01-28 (12 rows), the same CUSIP (fails-to-deliver data, `sec.py fails`).
- The registrant (CIK 924901) kept filing 8-Ks after the change, e.g. 2022-01-12, 2022-01-24, 2022-02-02

## 7. Why the library got it wrong

The library found no Form 25 and fell back to the continued-filings rule (code 304, `continued_filings_rule`,
flags `no_form25`, `delist_date_approx`, `successor_unknown`), reading the last sighting under CLI
(2021-12-10) as an exchange transfer. It never followed the same CUSIP to the VRE symbol. Cause tag:
`rename_not_followed`.

## 8. Fix and open checks

- Recognise that the CUSIP's fails rows continue under VRE (or the 8-K 5.03 rename) and emit no ending; extend
  `ticker_history` with VRE from 2021-12-10 (the observation run's last CLI sighting is 2021-12-10).
- Open check: the exact last session under CLI (2021-12-09 vs 2021-12-10) is only needed for the ticker range
  boundary; the 8-K says VRE trading commences with the effective date 2021-12-10.
- Golden case: yes, a clean rename on the same CUSIP with no Form 25, a rule fix should remove the ending.

## 9. Verification

Checked with `sec.py filings`, `grep`, `fails` (cache, then live SEC).

- **exit_kind: upheld.** The 8-K of 2021-12-07 (0001104659-21-147037, items 5.03, 7.01, 9.01) says the company
  changes its name to Veris Residential, Inc. effective 2021-12-10 and that "the Company's common stock, par value
  $0.01 per share, will commence trading on the New York Stock Exchange under a new ticker symbol VRE". Same
  common class, same exchange. `sec.py filings 924901` for 2021-11-15 to 2022-02-10 (forms 8-K, 25, 25-NSE, 15,
  8-A12B, 8-12B) lists only 8-Ks (2021-12-07, 12-13, 2022-01-12, 01-24, 02-02): no Form 25, no Form 15, no new
  registration. Fails rows for CUSIP 554489104: CLI 2021-11-02..2021-12-10, VRE 2021-12-16..2022-01-28, same CUSIP.
  Reference rule: same CUSIP, new ticker is not an ending.
- **last_trade_date: upheld, with a caveat.** The library's value is blank, so the field itself matches "none". It is
  wrong only because the row should not exist; the stock kept trading as VRE (fails rows to 2022-01-28). No
  evidence of a last trade.
- **value_rule: upheld, with a wording note.** The library publishes `transfer` (0.0 fill), an ending's rule. A
  rename pays nothing and is not an exit. The record's JSON says `continuation` while section 3 says none; both
  mean "not an exit" under the reference table.
- **ticker_history: upheld.** The library ends the security at 2021-12-10 under CLI
  (`BBG000CL1HL7,CLI,,2007-12-31,2021-12-10,observation`) with no VRE row, while the same CUSIP trades as VRE
  afterward. Open check stands: whether the last CLI session is 2021-12-09 or 2021-12-10 (the 8-K says VRE trading
  starts with the effective date 2021-12-10); it affects only the range boundary.

Result: all four fields upheld; no refutation found.
